## Option A: the owner's steps
You create the accounts. Secrets go only into Neon's and Render's dashboards, never into chat, a file or a commit.

### 1. Neon: a new project
1. Sign in at <https://console.neon.tech> (your existing account).
2. **New Project**: name `loyalty-support-demo`, Postgres **16**, and a region near Render's. For example, AWS US
   East (Ohio) with Render's Ohio region.
3. Open **Connect**. Choose the role **`neondb_owner`** and the database **`neondb`**, and turn **connection pooling
   off** (the demo creates its own roles and databases, which needs a direct connection). Copy the connection
   string. It starts `postgresql://neondb_owner:` and ends `?sslmode=require`.
4. Keep it for step 2.4. Don't paste it anywhere else.

### 2. Render: the Blueprint
1. Sign up at <https://dashboard.render.com> with **GitHub**.
2. When GitHub asks which repositories Render may see, choose **Only select repositories** →
   `vamsialladev/loyalty-support-modernization`.
3. **New → Blueprint** → pick the repository. Render reads `render.yaml` and shows one free web service,
   `loyalty-support-demo`.
4. It asks for **`DEMO_DATABASE_URL`**: paste the Neon string from step 1.3. `APP_SECRET_KEY` is generated by Render.
5. **Apply.** The first build takes several minutes. In the service's **Logs**, wait for
   `demo reset: removed 0 cases; mock world …`, then `Uvicorn running`.
6. Open the service's URL (`https://<name>.onrender.com`). The banner says
   "Public demo: mock AI, synthetic data. Resets every day.", and the sign-in page offers two buttons.
7. Tell me the URL. It isn't a secret. I'll run `uv run python scripts/demo_smoke.py <URL>` and the Playwright happy
   path against it, and record the result. The portfolio's "Live app →" link waits for Milestone 19, with the
   site's "wake up" note, as decided.

### What it does on its own
- **On every start** (and a free service starts after every sleep): sets up or checks the roles and databases and
  runs migrations. Once a day, it also empties the demo's cases and reloads the synthetic world.
- **Never:** live AI, an administrator account, password sign-in, or a public reset button.
- **Deploys:** only from `main`, and only when you press **Manual Deploy** (`autoDeploy: false`).

### If something goes wrong
| You see | Likely cause | Fix |
|---|---|---|
| `permission denied to create role` or `…database` in the logs | The string isn't the owner's, or pooling is on | Repeat step 1.3 with `neondb_owner` and pooling off; update the variable in Render; redeploy |
| The page takes about a minute | The free service was asleep | Expected; it stays awake while used |
| `Today's demo cases are used` | The daily cap (300 new cases) | Expected; it resets the next day |

`render.yaml`'s keys follow Render's Blueprint format. They're **unverified until you apply it**, because no Render
account exists yet. If Render rejects a key, tell me the message.
